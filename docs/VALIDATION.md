# 验证范围与已知限制

## 可重复执行的工程验证

```bash
python -m pip install -r requirements-dev.txt
python check_env.py --demo
python -m pytest -q
python demo.py --with-patients
```

测试覆盖：

- Python 源文件语法，以及真实主图和优化子图的执行。
- 三轮优化上限、满足条件后提前结束、否定词不被误判。
- 每轮人工确认及恢复、子图轮次显示、可选患者分支与汇总顺序。
- 阶段任务指令、必要工具证据、显式及嵌套错误检测、阶段超时。
- 可选临床预测失败时不保留 Agent 自行生成的概率。
- 确认令牌的一次性使用、过期请求和跨来源请求拒绝。
- 日志原子替换、写入失败保护、完整内容保留和运行 ID 校验。
- 本地 MCP 子进程在同一会话内连续调用，验证进程状态得以保留。

离线演示使用模拟节点；测试中的 MCP 工具是本地计数器，不加载药研模型。CI 执行这些工程检查，并生成可下载的演示 HTML / JSON。

## 已知限制

1. 完整模型环境和九个领域连接器尚未完成真实联调；DrugGen、Panacea、ChemFM、DrugAssist、MediTab 及对接工具需要各自的依赖与权重。
2. `stage_results` 提供阶段级证据记录，但尚未统一所有分子、端点、单位、来源及筛选结果的结构化契约。检测工具错误不等同于验证预测正确性。
3. 优化是否满足目标仍由 LLM 判断；现有口服生物利用度和毒性规则需要结合实际模型的端点语义重新验证。
4. 临床预测默认不可用。配置检查点后仍需验证单 logit 输出、正类定义、训练任务与校准质量；输出的 `validated` 为 `false`。
5. MemorySaver 仅支持进程内暂停恢复。JSON 日志用于回放，不支持进程重启后继续执行。
6. 阶段超时与步数限制不等于 token / 费用预算。超时可终止等待，但底层同步推理、远程请求或外部计算可能仍需服务侧取消机制。
7. LLM 请求最多重试两次，未对具有副作用的工具做自动重试；尚未建立全流程幂等与恢复策略。
8. 患者匹配仍使用 LLM 文本判断，处理失败会明确记录；未建立人工标注基准或准确率评测。
9. 人工确认面板面向本机使用，尚未实现多用户身份认证与审批持久化。

MCP 会话管理参考[官方客户端接口说明](https://github.com/langchain-ai/langchain-mcp-adapters/blob/main/langchain_mcp_adapters/client.py)。
